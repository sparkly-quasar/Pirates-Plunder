# Updates from the public releases, servers that update themselves, and a fix for phones
- **Check for Updates finds the latest release on GitHub.** On the main menu, it asks the game's public releases for the newest version and, on a Mac or Windows, offers **Update Now**: the game downloads it, checks every byte against the release's published fingerprints (SHA256SUMS.txt), installs it and restarts. No server or friend needed. If GitHub can't be reached, it asks the servers on your tailnet as before; on other computers it opens the releases page.
- **Servers keep themselves up to date.** A dedicated server checks the public releases every hour (and as soon as a newer copy tries to join), downloads a newer version, checks it against the release's fingerprints, and restarts into it once nobody is playing, with the same settings. Players then catch up from it as before. On by default with Docker and systemd (through the new `run.sh`); `auto-update=false` keeps a server on one version. To get this, update a server by hand one last time to 0.15.2.
- **Phones: the buttons at the bottom of the island stay on screen.** After typing (naming a recruit, say), an iPhone could leave the page scrolled, pushing the touch bar's buttons off the bottom. The page is now pinned in place, snaps back when the keyboard closes, and no longer zooms in on a text box.
- **Running a public server, step by step:** SERVER.md has a new walkthrough for a server anyone can play on: a small VPS, Docker, the firewall, and HTTPS for phones with Caddy. The server package now includes a ready-made `Caddyfile`, and the README has a short "Run a server" section.
- Releases now include the Mac app as a zip (`PiratesPlunder-mac.zip`), which Macs use to update themselves from GitHub, and SHA256SUMS.txt covers it.
- As always, copies on different versions update to match before playing together (from a friend, a server, or now GitHub).
