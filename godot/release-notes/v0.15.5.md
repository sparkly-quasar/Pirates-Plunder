# The server list finds a server even when its UDP status port goes quiet
- **The server list also asks over TCP.** Play on a Server asks each machine on your tailnet over UDP whether it runs a server. A machine that doesn't answer within two seconds is now also asked over TCP, on the same port number browsers use. On 4 November a server in Docker Desktop on a Mac stopped answering on UDP 24681 for a few hours while its other ports kept working, so desktop copies found nothing. A server found this way is listed as "answering over TCP only", and you can still join it as usual. Restarting its container brings UDP back.
- **When Tailscale is switched off, the game says so.** The server list and both Check for Updates buttons (on the main menu and on Play on a Server) now say that Tailscale is switched off on this computer and where to switch it on, instead of only "No servers answered". On a Mac, Tailscale can be switched off while the app is open and macOS still lists its VPN as connected.
- **A correction to the 0.15.4 notes:** the server's self-update wasn't what stopped UDP 24681. The port failed during a run with no update, and it kept answering through updates inside the container. Restarting the container for an update, new in 0.15.4, is harmless and stays.
- Fixed: a harmless error in the log when leaving a menu page right after opening it.
